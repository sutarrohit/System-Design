# Memcached Notes

## Overview

Memcached is a **distributed in-memory cache system** (not a database) written in C. It speeds up dynamic web applications by reducing database load — storing results of queries, API calls, and expensive operations in memory for fast retrieval.

It operates as a simple **key-value store** and supports distributed caching across multiple servers.

---

## Architecture Components

| Component                 | Role                                                                                                          |
| ------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Client Library**        | Communicates with Memcached servers; provides a simple interface for store/retrieve across multiple languages |
| **Memcached Server**      | Stores and retrieves data in memory; listens for incoming client requests                                     |
| **Storage Engine**        | Uses a hash table for key-value storage; applies LRU eviction to manage cache size                            |
| **Network Communication** | Simple ASCII-based protocol; supports store, retrieve, delete, increment/decrement                            |
| **Memory Allocator**      | Custom allocator that minimizes fragmentation and maximizes memory utilization                                |

---

## Indexing & Data Model

- Data is indexed using a **hash table**
- Each key is hashed → generates an index → value stored at that index
- On lookup: key is hashed → index found → value returned, or **"miss"** if absent
- Hash table is split into **buckets**, each managed by a server in distributed setups
- Missing data triggers forwarding to other nodes (**P2P-like architecture**)

### Why Hash Tables over Trees?

| Structure                   | Lookup Complexity | Notes                                    |
| --------------------------- | ----------------- | ---------------------------------------- |
| Hash Table                  | O(1) average      | Fast, ideal for caching                  |
| Binary Search Tree / B-Tree | O(log n)          | More complex; slower for cache use cases |

---

## Eviction Policy

- Default (and only built-in) policy: **LRU (Least Recently Used)**
- Since **v1.5+**, uses a **Segmented LRU**:
  - **HOT queue** — recently accessed items
  - **WARM queue** — items accessed more than once
  - **COLD queue** — items not recently accessed → evicted first
- **LFU, FIFO, Random, No-eviction** are **not natively supported** (use Redis for these)

---

## Common Use Cases

- **Web application caching** — cache DB query results, reduce load, improve response time
- **CDN** — cache images, videos, web pages at edge servers
- **Gaming** — store game state and player data
- **E-commerce** — cache product info, customer data, order history
- **Social networking** — cache profiles, friend lists, activity feeds

---

## Data Typically Stored

- Dynamic web content (HTML, images, multimedia)
- User session data (login info, shopping carts)
- Database query results
- API responses (third-party or internal microservices)
- Application-generated data (computation results, aggregations)

---

## Disk Storage

- Memcached is **memory-only** by default — no native disk persistence
- Twitter demonstrated Memcached on SSD (possible but non-standard)
- **Alternatives with disk support:**
  - **Redis** — in-memory + optional disk persistence
  - **Ehcache** — Java-based; supports "disk persistent" mode (dumps cache to disk on shutdown); scales from in-process to terabyte-sized caches

---

## Memcached vs Redis (Quick Comparison)

| Feature           | Memcached      | Redis                                    |
| ----------------- | -------------- | ---------------------------------------- |
| Data model        | Key-value only | Key-value + lists, sets, hashes, etc.    |
| Eviction policies | LRU only       | LRU, LFU, Random, TTL-based, No-eviction |
| Disk persistence  | ❌             | ✅ (RDB + AOF)                           |
| Replication       | ❌             | ✅                                       |
| Pub/Sub           | ❌             | ✅                                       |
| Simplicity        | High           | Moderate                                 |
